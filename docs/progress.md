# SIGNATE DX教育商材 購入予測コンペ — 作業記録

最終更新: 2026-08-21

## 1. コンペ概要

- **課題**: 架空の企業データから「従業員向けDX教育商材（e-learning / アセスメントツール等）を購入するか」を予測する二値分類（購入=1, 非購入=0）
- **評価指標**: F1Score（binary） — Precision と Recall のバランスを重視
- **データ**:
  - `train.csv`: 742行 × 43列（うち目的変数 `購入フラグ`）
  - `test.csv`: 800行 × 42列（ラベルなし、企業ID 742〜1541）
  - `sample_submit.csv`: 800行 × 2列（ヘッダーなし、`企業ID,予測値`）
  - `description.csv`: 各カラムの説明
- **クラス分布（train）**: 非購入 563件 / 購入 179件（陽性率 24.1%、不均衡データ）

### 変数の構成
| 種別 | 主なカラム |
|---|---|
| 企業基本情報 | 従業員数、業界（31種）、上場種別（PR/ST/GR）、特徴（BtoB/BtoC/CtoC）、事業所数、工場数、店舗数 |
| 財務三表（百万円） | 資本金、総資産、流動/固定資産、負債、短期/長期借入金、純資産、自己資本、売上、営業/経常/当期純利益、営業CF、減価償却費、運転資本変動、投資CF、有形/無形固定資産変動 |
| アンケート | アンケート1〜11（DX推進・満足度・技術導入状況などの5段階/2値評価） |
| 自由記述テキスト | 企業概要、組織図、今後のDX展望、企業名 |

### 主な欠損値（train）
- 工場数（403件）、店舗数（603件）… 業態による**構造的欠損**の可能性
- アンケート7（356件）… アンケート6が「いいえ」の場合の**構造的欠損**
- 営業利益(43)、経常利益(83)、事業所数(16)、資本金(6)、特徴(2)

## 2. 検証設計

- **5-fold Stratified CV**（`random_state=42`）で OOF（Out-Of-Fold）予測を作成
- 各サンプルは「学習に使われていないモデル」から予測されるため、OOF F1 を未知データ性能の推定値として利用
- OOF 予測全体に対し **F1 が最大となる閾値**を 0.05〜0.95 で探索し、その閾値を test に適用
- モデル: LightGBM（`objective=binary`）、クラス不均衡は `scale_pos_weight` で補正、early stopping（50）

## 3. 実施内容と結果

### 3.1 ベースライン (`notebooks/baseline.py`)
- 数値/カテゴリ列はそのまま利用（カテゴリはLightGBMネイティブ処理）
- テキスト列は**文字数のみ**を特徴量化
- 欠損値は LightGBM のネイティブ処理に委譲

**結果: OOF F1 = 0.6379（閾値 0.28）**
提出: `submission/baseline_submission.csv`

### 3.2 特徴量エンジニアリング (`notebooks/feature_eng.py`)
追加した特徴量:

| カテゴリ | 内容 |
|---|---|
| 財務比率 | 自己資本比率、ROE、ROA、売上高営業/経常利益率、流動資産比率、負債比率、有利子負債（比率）、一人当たり売上/営業利益、事業所あたり従業員数、フリーCF、減価償却費率、無形/有形固定資産変動率、ソフトウェア投資対有形固定資産比 |
| アンケート | DX前向きスコア合計/平均、戦略実感ギャップ（アンケート2−1）、導入済みフラグ、アンケート7欠損フラグ、セキュリティ整備度 |
| テキスト | DXキーワード出現数（企業概要/DX展望）、組織図内DX関連部署フラグ、組織図の行数、各テキスト文字数 |
| 構造的欠損 | 工場数/店舗数の欠損フラグ、店舗数・工場数の事業所数比 |

**結果: OOF F1 = 0.6635（閾値 0.27）** … ベースライン比 **+0.0256**
提出: `submission/feature_eng_submission.csv`

#### 重要度上位（gain）
1. 売上高経常利益率
2. 無形固定資産変動率
3. 売上高営業利益率
4. ソフトウェア投資対有形固定資産比
5. 無形固定資産変動(ソフトウェア関連)
6. **DXキーワード数_DX展望**（自由記述テキストが上位に寄与）
7. ROA / 従業員数 / 有利子負債比率 / 減価償却費率 …

### 考察
- 生の財務数値より「**率**」に変換した特徴量が支配的に効いた
- ソフトウェア関連の固定資産投資が購入意思の強いシグナル
- 自由記述（DX展望）のキーワードカウントも寄与しており、テキストのさらなる活用余地あり

### 3.3 TF-IDF テキスト特徴量 (`notebooks/tfidf_model.py`)
- 3.2 の構造化特徴量に、自由記述テキストの TF-IDF ベクトルを追加
- 対象テキスト: 企業概要 / 今後のDX展望 / 組織図
- 形態素解析: **janome**（wakati 分かち書き）で単語分割
- ベクトル化: `TfidfVectorizer`（1〜2gram, min_df=3, max_df=0.9）→ `TruncatedSVD` で各テキスト40次元に圧縮（LSA）
- **リーク防止**: TF-IDF + SVD の学習は各 fold の学習データのみで実施し、valid / test はそれで transform（fold内fit）
- SVD の 40次元 × 3テキスト = 最大120次元を数値特徴として LightGBM に投入

**結果: OOF F1 = 0.7168（閾値 0.26）** … feature_eng 比 **+0.0533**、ベースライン比 **+0.0789**
提出: `submission/tfidf_submission.csv`（購入予測 254件）
logloss も 0.33→0.30 前後まで低下しており、テキスト情報が明確に効いている。

### 3.4 特徴量v2/v3（EDA・エラー分析由来）
- v2 (`feature_eng_v2.py`): 業界target encoding(fold内fit)・アンケート軸再設計・姿勢語彙・生成AIフラグ等 → **OOF F1 0.7442**
- v3 (`feature_eng_v3.py`): 業界内zスコア/順位・財務総合スコア・テキスト財務乖離 → **OOF F1 0.7471**
- 学び: 手作り交互作用(満足×財務優良)は木モデルでは無効。財務指標の順位集約は有効(重要度2位)。
- v4 (`feature_eng_v4.py`): テキスト増量(char n-gram・品詞フィルタ)実験 → **0.71台に悪化**。742行では次元増が過学習を招く。

### 3.5 モデル変更が最大のブレークスルー（木→線形）
「モデルが悪い説」を検証。全て v3特徴量セット・fold内fitで比較:

| モデル | OOF F1 |
|---|---|
| LGB v3（旧チャンピオン） | 0.7471 |
| **LinearSVC (C=0.01, SVDテキスト)** | **0.8154** |
| LR (L2, C=0.1, SVDテキスト) | 0.8127 |
| SVC-RBF (C=10) | 0.8000 |

- 線形モデルが木モデルを **+0.068** 上回る。EDAでpoint-biserial相関を見ながら特徴設計したため関係がほぼ線形で、正則化の効いた線形モデルが最適。RBFでも線形に勝てず＝非線形の余地小。
- スクリプト: `lr_model.py` / `svm_model.py` / 共通特徴 `feat_lib.py`。

### 3.6 アンサンブル（`ensemble_model.py`）
- rank-average で統合。順位相関: 線形モデル同士は0.97-1.00でほぼ同一、LGBのみ0.83-0.86と異質。
- **「線形+LGB多様(4)」が最小構成で最高 OOF F1 0.8278**。弱いLGB(0.746)が多様性の源として最も貢献。

### 3.7 提出（`make_submission.py`）
- champion = LR_L2 + LinearSVC + LR_raw + LGB の rank-average。fold内OOFで閾値決定、全train再学習でtest予測。
- `submission/ensemble_submission.csv`（購入予測203件, 予測率25.4%）。
- **提出結果（LB）**: ベースライン 0.6486 → アンサンブル **0.7603**（+0.112）。

### 3.8 CV-LB乖離の検証（`validation_check.py` / `rank_lib.py`）
CV(OOF) 0.8248 vs LB 0.7603 で **0.065の乖離**。2つの仮説を2x2で検証（LB=0.7603）:

| 順位系 | 素朴閾値 | ネスト閾値 |
|---|---|---|
| 現行(全train順位) | 0.8248 | 0.8219 |
| fold内計算 | 0.8324 | 0.8262 |

- 閾値ネスト化の効果は −0.003〜−0.006 とごく小さい。
- 順位のfold内化はむしろCVが+0.008（＝全train順位はリークとして機能していない）。
- **結論: 乖離の主因はリークでも閾値でもなく「勝者の呪い（OOFで選び続けた選択バイアス）＋LBが少数サンプル」**。単一修正では消えない。
- 運用方針: 今後はCV絶対値を約0.06-0.07差し引いて解釈。CV改善は0.01以上で初めて有意とみなす。

### 3.9 「簡単な勝ち筋」探索と閾値プローブ
- 診断(`diag_quickwin.py`): IDリーク(r=-0.08)・train/test重複(0件)・決定的単独特徴(最大AUC0.67)いずれも無し。
- adversarial validation(`adversarial_validation.py` / `shift_investigate.py`): 全特徴ではAUC0.99だが**生特徴のみでは0.53**→ **分布シフトは無い**（0.99は順位系をtrain/test別計算した人工物）。train≒test。
- 公式チュートリアル(tutorial.ipynb)も標準的なLR＋閾値調整で、隠し技は無し。「train最適閾値がtest最適とは限らない」と明記。
- **結論: データの裏技一発の改善は存在しない**。乖離はCVへの過学習(勝者の呪い)＋LB少数サンプル。

**閾値プローブ（陽性率を振ってLB検証, `make_submission.py`）**

| 予測陽性率 | 陽性数 | LB F1 | CV(OOF) F1 |
|---|---|---|---|
| 21% | 168 | 0.7664 | 0.8000 |
| 25%(本命) | 203 | 0.7603 | 0.8248 |
| 30% | 241 | 0.7556 | 0.7910 |
| 35% | 280 | 0.7755 | 0.7608 |

- LB曲線が**非単調(W字)** → public LBは少数サンプルでノイズ大（分母~100規模の可能性）。差0.02は誤差範囲。
- **閾値では稼げないと確定**（0.756-0.776のバンド内）。乖離0.06は閾値では埋まらない=純粋な過学習。
- public LB追い(閾値の過剰最適化)は危険。1点の最良(35%)に賭けずCV最適近辺が安全。

### 3.10 追加検証（エラー分析→特徴 / LR単体）
- **内製/購入特徴**（error_dump.pyのエラー分析6社から仮説化）: 全データ検証で仮説と逆(外部購入語彙は買わない方向, r=-0.126)かつ既存アンケート7/10と冗長 → 追加でCV 0.8248→0.8194/0.8164に悪化、不採用。手作りテキスト特徴は一貫して効かないと再確認。
- **LR単体提出**（make_submission_lr.py）: CV 0.8205（アンサンブル0.8248とほぼ同等）だが **LB=0.7407**。同予測率21%で ensemble_rate21(0.7664) に負け。**単純モデルの汎化仮説は否定、アンサンブルの多様性(特にLGB)が実LBでも有効**と確認。

### 3.11 BERT/文埋め込みの検証（不採用）
- `extract_bert.py`(cl-tohoku BERT mean-pool) / `extract_sbert.py`(multilingual-e5-base) でテキスト3列を埋め込み化、PCA圧縮(fold内fit)してチャンピオンに投入。
- 結果（アンサンブルOOF, 現行TF-IDF=0.8248）:
  - 素BERT追加: 0.8101 / e5追加: 0.8052 / e5のみ(TF-IDF置換): 0.7810 — **すべて悪化**。
- 理由: このタスクの識別信号は「特定キーワードの有無」(生成AI・姿勢語彙)で、TF-IDFが直接捉える。文埋め込みは意味を平均化しピンポイントの語彙シグナルが薄まる。e5は意味的類似度用でトーン差判別に不向き。742行では高次元埋め込みが過学習。
- **結論: このデータではBERT/文埋め込みは効かない**。頭打ちの真因は「小サンプル×単語ベースの識別」。埋め込みは`features/bert_*.npy`/`e5_*.npy`にキャッシュ（.gitignore対象）。

## 5. 今後の改善候補（更新）
- **閾値・データ裏技は打ち止め**（検証済み・上限0.76-0.78バンド）。
- 残る大きなレバー: **BERT等の意味ベクトル**でテキストを質的向上（GPU利用）。
- コンペは精度だけでなく**考察・拡販戦略も評価対象**（課題文明記）。上位は分析ストーリーも重要 → 精度据え置きでインサイト整理に投資する選択肢。
- fold内順位版(rank_lib)の採用（僅かに良く方法論的にクリーン、ただしLBは変わらない見込み）。
- private LBを意識し public LBへの過学習を避ける。
